# Релизы Latest и обновления

Каждый успешный push в main (кроме docs-only) или ручной workflow_dispatch запускает unit/lint/build и phone/TV runtime tests. Только после их успеха publish-release собирает release APK с versionCode=1000+GITHUB_RUN_NUMBER, подписывает и публикует обычный релиз с отметкой Latest, без флага prerelease. Имя версии берётся из mjwatchVersionName, без суффикса -test.N. Для совместимости установленного updater сохраняется технический тег test-N. Существующие релизы не перезаписываются и не удаляются. APK, update.json и SHA256SUMS.txt находятся в GitHub Releases.

Одноразово установите APK нужной платформы из первого нового релиза поверх 0.2.1. В старой 0.2.1 механизма обновлений ещё нет. Application IDs прежние. После установки раздел «Настройки → Обновления» позволяет включить/выключить автоматическую проверку, проверить сейчас, скачать с отменой и открыть системный установщик. На главной показывается доступная версия. Автоматическая проверка выполняется при старте/возврате в приложение с ограничением раз в 15 минут. Найденная версия кешируется. Скачивание начинается по нажатию, установка требует подтверждения Android; бесшумной установки нет. На Android 8+ один раз разрешите установку из MJWatch.

## Подпись и доверие

По явному разрешению пользователя текущий локальный debug-keystore сохранён в GitHub Actions Secret MJWATCH_TEST_KEYSTORE_B64. Это тестовый канал, не отдельная production identity. Он сохраняет совместимость с установленными локальными APK 0.2.1. Private key не коммитится. Только publish job на main получает secret; pull requests его не получают. CI проверяет отпечаток сертификата по scripts/test-signing-cert.sha256 и завершает работу при несовпадении. Для будущего production-канала потребуется отдельное решение по ключу/миграции.

Updater использует отдельный HTTP client и публичный файл `releases/latest/download/update.json` только MJSasha/mj-watch, не обращается к REST API и не передаёт ключи Jackett/TorrServer/TMDB или cookies. Лимит анонимного GitHub API не участвует в проверке. HTTPS и allowlist GitHub/CDN обязательны. Проверяется schema/channel, платформа, immutable release URL, versionCode, размер, SHA256 и совпадение сертификата с установленным приложением. APK другой платформы/подписи и downgrade отклоняются. FileProvider открывает только cache/updates, не файлы настроек/БД. Частичный файл удаляется после ошибки/отмены. Обновление сохраняет Android sandbox/Keystore; приложение не удаляется.

## Выпуск

Обычный выпуск: push в main → зелёные проверки → автоматический релиз Latest. Ручной: Actions → Android → Run workflow → main. Документационные коммиты не создают релиз. Перезапуск уже опубликованного номера не перезаписывает assets: gh release create отклонит существующий tag. При сбое публикации до создания релиза можно повторить failed publish job. Для выпуска новой сборки используйте новый запуск workflow.

Source defaults (0.9.4/code1107) предназначены для локальной разработки; CI использует монотонные коды CI выше 1000. Релизные APK не debuggable, но подписаны согласованным тестовым ключом.
# Версии managed-сервера

Обновления APK сохранены отдельно. Сервер имеет собственную SemVer, версии API/schema и подписанную ZIP-поставку. Импорт и установка из приложения выполняются по SSH владельца с encrypted backup, health-check и откатом бинарников. [Процесс и доверие](../server/README.md).

С выпуска 0.5.0 серверная ZIP-поставка публикуется вместе с APK и включается в SHA256SUMS.txt. Стабильный ключ серверного тестового канала хранится в Actions Secret MJWATCH_RELEASE_SIGNING_KEY; приватный ключ не входит в Git или релиз. Подпись APK остаётся прежней. Тег test-N и channel=testing сохраняются для совместимости встроенного обновления; после проверок публикация автоматически создаёт обычный Latest, без замены старых assets. Метка channel=testing — совместимый формат updater, а не флаг prerelease GitHub. Перед следующим стабильным выпуском обновляйте mjwatchVersionName и changelog.

Для полного удаления и дедубликации устройств в 0.9.4 установите серверную поставку 0.1.6 через «Мой сервер → Обслуживание → Обновить сервер». APK сохраняет совместимость с 0.1.5; ID установки отправляется только если сервер объявляет поддержку.
