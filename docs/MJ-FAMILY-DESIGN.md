# Руководство по дизайну семейства MJ

Версия стандарта 1.0 · 15 ноября 2026 · MJReader, MJAnime, MJWatch

Это спецификация для последовательной унификации трёх приложений: от оформления репозитория и выпуска до цвета, иконок, компонентов, навигации и поведения экранов. Она задаёт целевой результат. Реализации переходят к нему постепенно, сохраняя данные, специальные функции и утверждённые продуктовые контракты.

**Как пользоваться:** открыть [иллюстрированное руководство](mj-family/guide.html), выбрать нужный компонент или сценарий, перенести его правила в задачу и проверить критерии приёмки. Значения для реализации находятся в [tokens.json](mj-family/tokens.json). Основания выбора, сравнение приложений и ссылки на исходники — в [исследовании](mj-family/RESEARCH.md).

Стандарт подготовлен по текущим локальным исходникам и существующим изображениям. Примеры компонентов в HTML — учебные образцы стандарта, а не проверенные экраны APK. Изображения приложений подписаны по происхождению. Принятие стандарта и внедрение в исходники — отдельные шаги.

## 1. Что именно унифицируем

| Берём из | Решения для семейства | Оставляем специфическим |
| --- | --- | --- |
| MJReader | Вход в репозиторий, карта ответственности, adaptive layout, сохранение позиции, семейный icon master, спокойные surfaces, живой preview настроек | Типографика книги, Scroll/Pages, RSVP, сноски, Dusk/Sepia |
| MJAnime | D-pad, явный фокус, rail без подписей, кинематографичный hero, постоянные номера серий, озвучки и сезоны | TV-оболочка, Anime4K, конкретные API и история |
| MJWatch | Отдельные mobile/TV оболочки, tablet master/detail, независимые подключения, этапы подготовки потока, экран обновлений | Раздачи, TorrServer, Jackett/JacRed и необязательный TMDB |

### MJ-001 Общая основа

Общими являются роли цвета, бренд, геометрия, типографические роли, семантика иконок, состояния, доступность и документация. Их реализация остаётся на существующем стеке: Views/Java, Flutter/Kotlin, Compose/Kotlin.

### MJ-002 Границы унификации

Новый framework, общий runtime, monorepo, cloud sync или единый сетевой SDK не являются условием унификации. Общий пакет появляется только при доказанном повторении кода в совместимых стеках.

### MJ-003 Специализация

Приложение сохраняет собственный сценарий. Библиотеке Reader не нужен рекламный hero; Anime не получает телефонную оболочку автоматически; Reader не получает торренты.

### Обязательные и рекомендательные правила

Правило с **ДОЛЖНО** — критерий приёмки. **СЛЕДУЕТ** — значение по умолчанию, которое можно заменить обоснованным исключением. **МОЖНО** — допустимый вариант. Код правила остаётся постоянным при редактировании текста.

Исключение содержит приложение, ID правила, причину, замену, проверку и условие пересмотра. «Так уже сделано» не является достаточным обоснованием. Явные действующие решения владельца и совместимость пользовательских данных имеют приоритет; конфликт фиксируется в задаче, а не разрешается скрытым изменением поведения.

## 2. Репозиторий как часть продукта

### REP-01 Структура и точки входа

Репозиторий ДОЛЖЕН иметь README, AGENTS, CONTRIBUTING, CHANGELOG, карту архитектуры, руководство по тестам и выпуску. Существующее расположение файлов сохраняется; ссылки связывают их в одну карту.

```text
README.md
AGENTS.md
CONTRIBUTING.md
CHANGELOG.md
STATUS.md                    если нужна текущая сводка
.editorconfig
.github/
  ISSUE_TEMPLATE/bug.yml
  pull_request_template.md
  workflows/
docs/
  ARCHITECTURE.md
  TESTING.md
  RELEASING.md
  DESIGN.md                  ссылка на стандарт и локальные исключения
  images/                    отобранные изображения продукта
  history/                   исторические решения
```

Исходники НЕ ДОЛЖНЫ перемещаться в новую структуру только ради совпадения дерева. Design masters остаются в существующих каталогах. У каждого контракта одно основное место, остальные файлы ссылаются на него.

### REP-02 README

Порядок: banner → badges → скачать/установка → короткое назначение → основной screenshot → возможности → ограничения → сборка → документация. СЛЕДУЕТ ограничиться 3–4 полезными badges: checks, release, Android minimum, стек.

**Хорошо:** «MJReader — Android-приложение для EPUB, FB2 и TXT с локальной библиотекой и RSVP». **Плохо:** «Самая мощная платформа для всего контента» без описания сценария.

Изображения ДОЛЖНЫ иметь alt, понятное происхождение и демонстрационные данные. Главный экран показывается крупно; вторичные — отдельной группой. Нельзя публиковать личные книги, истории, адреса серверов и токены. Для разных приложений указывать их реальный Android minimum: Anime API 24+, Reader/Watch API 26+ на момент исследования.

### REP-03 AGENTS и архитектурная карта

AGENTS ДОЛЖЕН содержать назначение, быстрые команды, карту нужных файлов, продуктовые инварианты и ограничения работы. Детали реализации выносятся в ARCHITECTURE. История — в history/CHANGELOG.

Карта ДОЛЖНА отвечать: кто владеет состоянием; где меняется экран; где хранятся данные; что делает сеть; какие проверки соответствуют задаче. Хороший пример: «Фокус/тема Reader → ReaderOptions; диалоги → ReaderDialogs; иконки → ReaderIcon».

### REP-04 Изменения и ревью

PR ДОЛЖЕН объяснять проблему, итоговое поведение, проверку и существенное ограничение. Для визуального изменения нужны до/после в одинаковом окне и состоянии, плюс ссылки на затронутые правила.

```text
Проблема: при font scale 2 кнопки подтверждения выходят за диалог.
Результат: действия располагаются вертикально, содержимое прокручивается.
Правила: CMP-09, A11Y-01, QA-02.
Проверка: narrow + short landscape, Light/Dark, keyboard/Back.
```

### REP-05 CI и выпуск

Toolchain/lockfiles ДОЛЖНЫ быть воспроизводимы; Actions СЛЕДУЕТ закреплять SHA. Минимальные permissions, offline fixtures, отдельные checks/release, логи ошибки и ограниченное хранение артефактов обязательны для нового процесса.

Текущие команды: Reader `bash scripts/checks.sh`; Anime `make check`, для native `make native-test`; Watch `sh scripts/check.sh`. Унификация не требует переименования команд.

APK, ключи, токены, local SDK paths и пользовательские выгрузки НЕ ДОЛЖНЫ попадать в Git. Лицензии шрифтов, fork, shaders и demo media сохраняются. Публичность репозитория не заменяет лицензию проекта.

## 3. Бренд и семейство иконок

### BRD-01 Название и знак

Названия: MJReader, MJAnime, MJWatch. Монограмма MJ ДОЛЖНА использовать точные path и пропорции мастера Reader. Внутри launcher знак не набирается текстом. UI wordmark МОЖЕТ использовать Roboto: MJ в primary, остальная часть в onSurface.

Источник: `MJReader/design-system/mj-family/reader-icon.svg`, правила `ICONS.md`. Фон launcher `#141925` намеренно отличается от UI background `#0C0E15`. Это разные роли.

### BRD-02 Геометрия launcher icon

| Параметр | Значение |
| --- | --- |
| Canvas | 108×108 единиц |
| Фон | Full bleed, `#141925` |
| Foreground | `#C7FF68`, прозрачный фон |
| MJ | Неизменный path; stroke 4.5; round caps/joins |
| App symbol | Slot x=42–66, y=66–80; stroke 2.5 |
| Safe circle | Центр 54/54, радиус 33 |
| Проверочные размеры | 32, 48, 64 px и увеличенный preview |

Reader сохраняет книгу; Anime — play. Для Watch СЛЕДУЕТ выбрать кадр/киноплёнку как предметное отличие. **Точный символ Watch пока не утверждён**: примеры стандарта показывают существующий мастер Reader, а не выдают новый знак за готовый.

### BRD-03 Варианты и запреты

ДОЛЖНЫ быть adaptive foreground/background, monochrome без непрозрачного фона, отдельная notification silhouette и отдельный TV banner там, где он нужен. Android выбирает маску; круг и rounded square не запекаются в adaptive layers.

**Правильно:** точный знак, плоские цвета, один предметный символ. **Неправильно:** gradient, shadow, badge версии, отдельная буква приложения, растянутый play, увеличение MJ у одного продукта, прямоугольный TV banner в роли launcher icon.

См. [Android adaptive icons](https://developer.android.com/develop/ui/compose/system/icon_design_adaptive). У MJWatch существующий manifest использует banner как icon: это задача миграции, а не образец для копирования.

## 4. Цветовые токены

### COL-01 Общие роли

В компонентах ДОЛЖНЫ использоваться семантические роли. Новые screen-specific hex не допускаются без объяснённой роли и пары dark/light. Значения ниже — целевой набор 1.0; имена адаптируются к toolkit через явное отображение.

| Token | Dark | Light | Назначение |
| --- | --- | --- | --- |
| background | #0C0E15 | #FAFAF7 | Основа экрана |
| surface | #191E29 | #EAEDE6 | Карточка, группа, навигация |
| surfaceHigh | #242B39 | #E1E5DC | Вложенный control |
| onSurface | #F0F2EC | #20251F | Основной текст |
| onSurfaceVariant | #ABB5C5 | #4D584E | Вторичный текст |
| primary | #C7FF68 | #345A05 | Основное действие, акцент |
| onPrimary | #0C0E15 | #FFFFFF | Текст/иконка на primary |
| primaryContainer | #303D28 | #DCE9CB | Выбранный спокойный контейнер |
| onPrimaryContainer | #C7FF68 | #345A05 | Текст на primaryContainer |
| outline | #68778D | #687267 | Значимая граница |
| error | #FFB4AB | #A32323 | Ошибка на background/surface |
| warning | #F1C879 | #775500 | Предупреждение на background/surface |

`error` и `warning` — foreground роли, не произвольные фоны для белого текста. В версии 1.0 ошибки оформляются текстом/иконкой на обычной surface; отдельные filled error-container не вводятся. При отображении на Material ColorScheme нужно определить совместимые error/onError/container роли и проверить фактическое использование.

### COL-02 Допустимые сочетания

| Поверхность | Разрешённый текст |
| --- | --- |
| background / surface / surfaceHigh | onSurface, onSurfaceVariant, primary, error, warning после проверки пары |
| primary | Только onPrimary |
| primaryContainer | onPrimaryContainer; основной текст onSurface при проверенной паре |
| Изображение | Белый/светлый текст только с измеренным scrim |

Контраст обычного текста ДОЛЖЕН быть ≥4.5:1; значимых иконок и границ ≥3:1. Нельзя использовать lime с белым текстом или автоматически инвертировать палитру. Сгенерированная HTML-таблица показывает измеренные пары базовых непрозрачных цветов; она не сертифицирует композицию с фотографией.

### COL-03 Выбранность и интеракция

Primary CTA filled; selected container спокойный; focus ring контрастный. Ошибка ДОЛЖНА иметь текст, а не только красный контур. У disabled есть native semantics и отсутствие действия; понижение opacity не является единственным признаком блокировки, если причина неочевидна.

Дополнительные Dusk/Sepia Reader сохраняются. System theme и dynamic color не добавляются в продукт автоматически. Бренд launcher не меняется при выборе Sepia.

## 5. Типографика и форматирование контента

### TYP-01 UI type scale

UI использует Android sans/Roboto; 400 body, 500 labels, 700 важные заголовки. При отсутствии начертания допускается системное отображение, но не новая декоративная гарнитура. Читательская гарнитура отдельно от UI.

| Роль | Touch: size / line height, sp | TV: size / line height, sp | Weight |
| --- | --- | --- | --- |
| hero | 34 / 40 | 40 / 48 | 700 |
| screenTitle | 28 / 36 | 32 / 40 | 700 |
| sectionTitle | 22 / 28 | 24 / 32 | 700 |
| title | 18 / 24 | 20 / 28 | 500 |
| body | 16 / 24 | 20 / 28 | 400 |
| secondary | 14 / 20 | 18 / 24 | 400 |
| label | 14 / 20 | 18 / 24 | 500 |
| metadata | 12 / 16 | 16 / 24 | 400 |

Это целевые роли, а не приказ заменить все числа одновременно. TV размеры требуют визуальной калибровки на реальном расстоянии. Значимые действия не оформляются metadata-текстом. Font scale применяется системой; 2× не заменяется уменьшением базового шрифта.

### TYP-02 Переносы и числа

Заголовок сеточной карточки: до двух строк; книги без обложки — до трёх в типографическом fallback. Полное название ДОЛЖНО быть доступно на детали. В dialog header максимум две строки с доступным полным именем; тело прокручивается.

Позиции и таймеры используют стабильную ширину цифр, где toolkit позволяет. Видео `3:59 / 24:00`, номер `Серия 3`; книга `33%`; размеры `1,4 ГБ` по локали. Единицы не теряются при переносе. Неизвестное значение — «Не указано» или отсутствие поля; `0` означает настоящий ноль.

UI не придумывает описание, автора, рейтинг, bitrate, codec, сиды или длительность. Длинные URL и технические имена переносятся; обычный русский текст не разбивается посреди каждого слова.

## 6. Отступы, форма и слои

### GEO-01 Шкалы

| Token | dp | Использование |
| --- | --- | --- |
| space.1 / 2 / 3 | 4 / 8 / 12 | Микроритм, gap действий, подписи |
| space.4 / 5 / 6 | 16 / 20 / 24 | Padding, стандартный gutter, секции |
| space.8 / 10 / 12 | 32 / 40 / 48 | Большие разделения |
| radius.badge | 8 | Статусная метка |
| radius.selector | 12 | Chip и компактный control |
| radius.control | 16 | Кнопка, карточка |
| radius.group | 20 | Группа, dialog |
| radius.sheet | 28 | Верх sheet |
| target.min | 48 | Минимальная область действия |
| button.primary.minHeight | 52 | Главная touch CTA |
| icon.default / small | 24 / 20 | Размер символа, не hit area |
| focus.width / offset | 2 / 4 | Outline и внешний отступ карточки |

Внутренний padding группы 16 dp. Между соседними действиями 8 dp, секциями 24–32 dp. Touch gutter: 16 dp до 360 dp доступной ширины, иначе 20 dp; wide layout 24–32 dp. Это ДОЛЖНО учитывать insets, а не заменять их.

### GEO-02 Форма и elevation

Стандартный экран плоский. Поверхности различаются цветом и отступом, а не постоянными тенями. Pill допускается для primary CTA и коротких filters; все строки настройки не превращаются в pills.

Семейный акцент — спокойный диагональный градиент `surfaceHigh → surface` от верхнего левого к нижнему правому углу. Его МОЖНО применять к одному смысловому блоку в видимой области: статусу процесса, продолжению или выделенной настройке. Остальные поверхности остаются однотонными. Это постоянный фон, без анимации и зернистого мерцания; стандартный ripple остаётся только обратной связью на нажатие. Цвета берутся из текущей темы; контраст текста, иконок и фокуса проверяется по всей площади. Градиент не вводится в launcher/notification icon, primary CTA, каждую строку списка или под текст поверх artwork.

Слои: content → sticky chrome → anchored menu/sheet → modal scrim/dialog → системный installer/IME. Только верхний modal получает input. Focus ring не обрезается clip карточки или viewport; между карточками остаётся место для него.

## 7. Адаптивность и навигационные оболочки

### LAY-01 Решение по окну

| Доступная ширина | Touch-профиль | Правило |
| --- | --- | --- |
| <600 dp | Compact | Одна основная колонка; bottom navigation там, где нужны destinations |
| 600–839 dp | Medium | Rail при достаточном месте; широкий контент без обязательных двух панелей |
| ≥840 dp | Expanded | Можно master/detail при сохранении читаемой ширины каждой панели |

Если font scale ≥1.6 или высота <400 dp, layout ДОЛЖЕН отдельно пересматриваться: перенос действий, меньше колонок, прокрутка dialog. Широкая геометрия не гарантирует две панели. Существующие предметные пороги Reader сохраняются до регрессионной проверки.

См. [Android window size classes](https://developer.android.com/develop/ui/compose/layouts/adaptive/use-window-size-classes). TV выбирается по назначению оболочки и вводу, а не только по ширине.

### NAV-01 Phone destinations

Watch: Главная, Поиск, Моё, Настройки. Иконки с подписями; выбранность видна даже без цвета. Деталь, список файлов и плеер — вложенные сценарии, не новые tabs.

Reader: библиотека — стартовая точка; «Добавить книгу» и «Найти книги» — действия, а не искусственные tabs. При чтении приложение показывает собственные contextual controls.

### NAV-02 TV rail и фокус

Anime/Watch TV: rail слева, постоянные видимые подписи не показываются. Доступное имя обязательно; tooltip при фокусе МОЖНО, если он не двигает контент. Selected destination — тональная surface, keyboard focus — отдельный outline.

Одновременно один логический focus. Стрелки ДОЛЖНЫ вести к пространственно ожидаемому соседу. Уже видимый control не прокручивается ради центрирования. В конце ряда не должно быть случайного ухода в скрытую область.

### NAV-03 Back и возврат

Back сначала закрывает верхний слой/IME, затем возвращает в предыдущий экран по действующему контракту платформы и продукта. Закрытие modal возвращает focus на инициатора. После удаления — на ближайший доступный элемент. Query, scroll и selection сохраняются.

В Anime Back в плеере сохраняет существующее правило выхода; нельзя подменить его новым универсальным поведением «сначала только спрятать controls». Удержание OK не запускает короткое действие. Детали [TV focus system](https://developer.android.com/design/ui/tv/guides/styles/focus-system).

## 8. Каталог компонентов

Каждый компонент ниже описывает внешний вид, действие, состояния, доступность и пример. Новая реализация ДОЛЖНА покрывать все применимые состояния, а не только normal screenshot.

### CMP-01 Primary button

**Когда:** одно главное действие в текущем контексте: Продолжить, Скачать, Добавить книгу. **Вид:** primary/onPrimary, minHeight 52 dp touch, horizontal padding 24 dp, radius.control или согласованный pill, label 500. Иконка optional 20–24 dp и gap 8 dp.

**Состояния:** default, pressed, focused, disabled, loading. Loading сохраняет размеры и меняет подпись по действию: «Скачиваем…». Повторное нажатие не создаёт дубль; отмена, если предусмотрена, отдельным доступным действием.

**TV-профиль:** основная кнопка от 52 dp, вторичная от 48 dp, radius 16 dp; label 18/24 sp, weight 500, padding 24/20 dp по горизонтали и 12 dp по вертикали. Focus сохраняет исходную заливку и добавляет кольцо primary толщиной 2 dp с внешним зазором 4 dp. Pressed уменьшает яркость заливки и текста до 85%; размер и shape остаются прежними. Disabled композитит обычную кнопку с opacity 45% поверх background, сохраняя её оттенок. Loading оставляет полную яркость, показывает native indicator 20 dp / stroke 2 dp перед подписью и сообщает busy/disabled state. В кнопке фиксированной ширины загрузка не меняет геометрию; отмена остаётся отдельным действием. Фокус и нажатие не масштабируют кнопку.

**Доступность:** role Button, полное имя, enabled/loading state. Иконка рядом с текстом не озвучивается повторно. Focus outline должен быть виден также на lime fill.

**Хорошо:** один «Продолжить», рядом secondary «С начала». **Плохо:** одинаково яркие «Продолжить», «В список», «Назад» в одном блоке.

### CMP-02 Secondary и text action

**Когда:** настройка, переход, отмена, дополнительное действие. **Вид:** surface/onSurface, minHeight 48, padding 16–20, radius.control; text action без постоянного filled frame. Press/focus остаются видимыми.

Не делать disabled только потому, что действие вторично. «Закрыть» в header dialog — text/icon action; не дублировать его второй кнопкой «Готово» без отдельного смысла.

### CMP-03 Icon button

24 dp символ внутри минимум 48×48 dp; hit area не пересекается с соседней. Контекстное имя: «Настройки чтения», «Действия с книгой Станция Тишина», а не «Шестерёнка»/«Три точки». Toggle сообщает выбранность.

Resting фон МОЖЕТ совпадать с экраном. Press локальный, focus outline обязателен. Native button semantics сохраняются при собственном рисовании.

### CMP-04 Tabs, chips и badges

**Tab:** переключает взаимоисключающие панели одной детали; label + underline, focus отдельно. **Filter chip:** меняет набор элементов; selected tonal container и state. **Badge:** сообщает факт, сам не нажимается и не получает fake button semantics.

Tabs: «Серии / Информация / Сезоны». Chips: «Все / Читаю / Избранное». Badges: «1080p», «Серия 3». При font scale 2 chips СЛЕДУЕТ переносить или давать предсказуемую прокрутку; скрытое значение можно раскрыть, а не молча обрезать до двух букв.

### CMP-05 Poster card

Изображение 2:3, название до двух строк, вторичная строка автора/года/типа. Контейнер radius.control, padding 8–12, gap 8. Размер карточки рассчитывается из доступной ширины; target каждой интеракции ≥48 dp.

Book cover — Fit/Contain, не отрезать текст обложки. Film poster МОЖЕТ crop по согласованному фокусу. Декодировать под фактический размер. Placeholder сохраняет ratio.

Tap/OK открывает предметную деталь или книгу по контракту продукта. Меню — отдельная action; карточка не содержит второй дублирующей кнопки открытия. Focus ring не меняет размеры. Large font → меньше колонок или list.

### CMP-06 Continue card

Название + реальная позиция обязательны. Видео: серия, время/длительность; Reader: процент и компактная обложка. Progress bar supplemental: те же данные доступны текстом/semantics.

Для книги можно использовать существующий compact cover 40×60 dp; вся карточка остаётся большой target. Для видео — кадр 16:9 или poster thumbnail. «Продолжить» не обещает запуск, если карточка по контракту сначала открывает detail: Anime открывает detail и продолжение находится там.

**Пограничные состояния:** позиция неизвестна — не рисовать 0%; завершено — показать статус, не вечную загрузку; предмет удалён — убрать запись с предсказуемым focus.

### CMP-07 Episode card и release row

Episode: 16:9, постоянный номер отдельным контрастным блоком, caption, статус просмотра при наличии. Обратная сортировка НЕ ДОЛЖНА перенумеровывать серию. Озвучка и сезон — отдельные selectors.

Release row Watch: имя, supplied quality/size/seeds/language; primary выбор отдельно от информационных badges. При неизвестных данных выводить «Сиды не указаны», а не 0. Длинное техническое имя переносится. Отличие release от фильма ДОЛЖНО быть понятно текстом.

### CMP-08 Text field и поиск

Постоянная видимая label, minHeight 56 dp как стартовый профиль, radius.selector/control, padding 16, surface или surfaceHigh. Default outline при необходимости 1 dp; focused 2 dp primary; invalid 2 dp error + inline текст.

Пример: label «Адрес TorrServer»; hint «http://192.168.1.10:8090»; error «Укажите полный адрес с http:// или https://». Текст ошибки задаётся фактической проверкой, а не общим «Ошибка».

IME системная; правильный inputType; paste и password manager не блокируются. Поиск сохраняет query при Back и ошибке. Clear имеет имя. Пароль скрыт; toggle «Показать пароль»/«Скрыть пароль». Ошибка не стирает ввод.

### CMP-09 Dialog и sheet

Dialog: radius.group, padding 24 dp на обычном окне, gap 16/24; fixed header с доступным закрытием, scrollable body. Кнопки 48 dp, gap 8. В узком окне или font scale ≥1.6 — вертикально, основное действие последним в порядке чтения.

Содержание и действия ДОЛЖНЫ быть достижимы при IME и высоте <400 dp. Закрытие по Back сохраняет исходное состояние, если нет явно подтверждённого save. При несохранённом значимом вводе нужен определённый контракт сохранения/отмены.

Sheet quick typography Reader МОЖЕТ быть без dim, поскольку пользователь сравнивает текст. Modal выбора/подтверждения использует scrim и ограничивает focus верхним слоем. Focus возвращается на инициатор. Нельзя перекрывать диалогом важный control и оставлять его активным под scrim.

### CMP-10 Settings row и switch

Группа имеет heading, surface, padding 16. Строка: optional outline icon, название, текущее значение и affordance перехода; минимум 48 dp, фактическая высота растёт с текстом. Разделитель не заменяет отступы.

Switch используется только для on/off, немедленно сообщает новое состояние. Изменение, требующее Save, не маскируется под мгновенный switch. Вся строка и переключатель не должны дублировать активацию. Недоступная настройка объясняет причину.

### CMP-11 Slider и preview

У slider есть label, текущее значение, доступные шаги и keyboard/accessibility actions. Track визуально тонкий, область взаимодействия ≥48 dp. Изменение typographic preview происходит во время drag; дорогая repagination Reader — после release.

Пример: «Размер текста · 20 sp», рядом ограниченный excerpt. Смена размера не теряет позицию. Preview не является второй независимой книгой и не запускает сеть.

### CMP-12 Loading, progress и status message

Неопределённое ожидание — indicator + этап. Известный размер — progress + текст. Нельзя показывать придуманный процент. Отмена не становится «Ошибка»; после неё доступен следующий логичный шаг.

Сообщение статуса не переносит focus само по себе. Для accessibility обновлять осмысленную фразу, не спамить процентом каждый кадр. Reduced motion делает indicator статичным, но сохраняет объяснение ожидания.

### CMP-13 Empty и error state

Композиция: короткий заголовок → причина/следующий шаг → одно предметное действие. «В библиотеке пока нет книг» / «Добавьте EPUB, FB2 или TXT» / «Добавить книгу».

Ошибка сети не должна превращать всю библиотеку в пустой экран. Частичные результаты сохраняются. Inline ошибка связана с полем; экранная ошибка — с операцией и Retry. Техническая диагностика раскрывается отдельно и не содержит секретов.

### CMP-14 Menu и удаление

Context menu не повторяет главное действие карточки без необходимости. Опасное действие подписано конкретно: «Удалить из истории», «Переместить в удалённые». Нельзя подписывать «Удалить», если это означает удаление файла на общем сервере, не объяснив область действия.

Reader использует Deleted/Restore; Watch сохраняет existing undo там, где поддерживается. Если операция необратима, подтверждение ДОЛЖНО назвать объект и последствия. Долгое OK/press — shortcut, не единственный доступный путь к важному действию.

### CMP-15 Update panel

Установленная версия, доступная версия, release notes, автопроверка, ручная проверка и download/install statuses. Download начинается по действию пользователя; установку подтверждает Android. Error update не блокирует чтение/видео.

Статусы: checking → available/current → downloading → verifying → ready to install → system installer; error/cancelled там, где применимо. Не заявлять «Установлено» до подтверждённого результата. Неверный package/signature/hash прерывает цепочку и объясняется пользователю.

## 10. Композиции экранов

### SCR-01 Главная TV

Порядок: rail → edge-to-edge hero в контенте → title/metadata/одна CTA внизу слева → полка продолжения → подборки. Hero без enclosing rounded frame; верх и правая часть кадра светлые. Scrim локален под controls; короткий нижний fade соединяет с background.

Hero соответствует сфокусированному объекту. Backdrop → кадр → poster → neutral fallback только того же тайтла. Нельзя брать чужой artwork. Carousel не авторотируется. Смена категории не должна внезапно убирать продолжение или двигать focus.

**Пример:** MJAnime главная из иллюстраций — композиционный ориентир. В Watch нынешний полноразмерный horizontal scrim требует отдельной визуальной коррекции; исходный screenshot не означает, что все правила уже соблюдены.

### SCR-02 Главная телефона Watch

Title/connection action → categories → rounded hero → Continue → каталог → bottom destinations. Hero допускает 34 sp title и большую primary CTA. На узком/large-font окне изображение не отнимает доступ к первому действию; разделы остаются прокручиваемыми.

Кнопка «О фильме» открывает detail; «Смотреть» не используется, если следующий шаг только информация. На экране не должно быть одновременно нескольких равнозначных lime CTA.

### SCR-03 Библиотека Reader

Один fixed masthead → search/filters → компактное продолжение → adaptive grid/list → нижние предметные действия. Обложка сохраняется целиком; карточка открывает книгу; menu отдельное. Колонки зависят от доступной ширины и font scale, не от имени устройства.

При large text — меньше колонок, при необходимости list. Пустая библиотека предлагает import. Ни search, ни нижняя панель не перекрывают последнюю карточку.

### SCR-04 Деталь тайтла

Название, год/тип/рейтинг при наличии, основное «Продолжить»/предметное действие, restart и сохранение вторично, затем tabs и содержимое. В Anime постоянные номера серий, сезоны/озвучки сохраняются. Short OK из истории открывает detail.

В Watch фильм, раздача и файл ДОЛЖНЫ восприниматься как разные сущности. Замена источника не переносит позицию автоматически без подтверждённого соответствия.

### SCR-05 Чтение и RSVP

Текст — фиксированный viewport; overlays не вызывают repagination/scroll. В Pages края переключают страницу, центр показывает controls; сноска имеет приоритет над edge tap. Scroll не показывает неработающие arrows.

RSVP: слово → Start/Pause → speed; seek раскрывается по действию. Уход в фон ставит паузу. Live typography preview ограничен по размеру; тяжёлый reflow не запускается каждый tick slider.

### SCR-06 Настройки

Разделы: Подключения; Чтение/Воспроизведение; Оформление; Обновления; О приложении. Не показывать отсутствующие предметные разделы ради симметрии. В Reader настройки контента стоят раньше общих технических параметров.

Каждый сервис Watch — отдельная страница и независимый check. Save и Check connection — разные действия. Offline save допустим там, где есть такой контракт; UI не заявляет, что соединение проверено, если оно только сохранено.

## 11. Сценарии и состояния

### FLW-01 Поиск

Пустой запрос → ввод через OS IME → loading → content / empty / partial / error. Query сохраняется. Новый запрос отменяет или делает неактуальным старый; поздний старый ответ не заменяет новую выдачу. Back из detail возвращает selection и scroll.

### FLW-02 Подготовка видео Watch

Поиск → раздача → metadata/files → выбор файла → подготовка потока → первый кадр. Каждый этап имеет собственное название и cancel там, где это возможно. Не путать добавленный torrent и готовый video stream.

| Ситуация | Текст по фактическому состоянию | Действие |
| --- | --- | --- |
| Сервер не ответил | TorrServer не ответил. Проверьте адрес или повторите позже | Проверить адрес / Повторить |
| Файлы ещё не получены | Раздача добавлена. Ожидаем список файлов | Отменить ожидание |
| Каталог недоступен | Каталог недоступен. Прямой поиск раздач доступен | Открыть поиск |
| Пустая выдача | По запросу ничего не найдено | Изменить фильтры |
| Часть источников недоступна | Показаны доступные результаты. Не ответили … | Повторить недоступные |

Эти фразы применяются только при соответствующем доказанном состоянии. Внутренние stack traces и токены не показываются.

### FLW-03 Плеер Anime

Существующий контракт: при скрытом UI Left/Right перематывают, Up показывает выход, Down — play/pause; с нижних controls Up → шкала → скрыть. Подсказка opening/next episode доступна с пульта, но не крадёт focus у modal.

GPU Off по умолчанию. Смена режима сохраняет позицию, паузу, качество и озвучку. Фактический fallback показан как fallback; нельзя выдавать его за активный CNN.

### FLW-04 Импорт и удаление Reader

Выбор файла → ограниченный background import → per-file result → открытие/библиотека. Повторный импорт/repair сохраняет identity, полный текст, progress и notes по действующему контракту. Удаление из библиотеки обратимо через Deleted.

### FLW-05 Общая таблица состояний

| Состояние | Содержимое | Фокус и действие |
| --- | --- | --- |
| Initial | Понятная отправная точка | На первом полезном control |
| Loading | Этап; progress только при известном значении | Не красть focus; cancel если есть |
| Content | Реальные данные | Стабильный selection |
| Empty | Причина, один следующий шаг | На полезном действии |
| Partial | Доступный контент и локальное объяснение | Retry не сбрасывает список |
| Error | Конкретная причина и восстановление | Сохранён ввод; ошибка связана с операцией |
| Cancelled | Явная отмена без ложной ошибки | На безопасном следующем действии |
| Offline/stale | Только реально существующие local/cache данные | Объяснить ограничения, не блокировать независимый сценарий |

## 12. Движение и обратная связь

### MOT-01 Tokens

| Token | Значение | Назначение |
| --- | --- | --- |
| immediate | 0 ms | Непосредственное состояние нажатия/фокуса |
| quick | 120 ms | Локальное небольшое изменение |
| reveal | 180 ms | Нужная прокрутка/раскрытие |
| overlay | 200 ms | Появление controls поверх контента |
| reduced | 0 ms для spatial motion | Сохранение смысла без движения |

Длительности — целевой профиль, не обязательная анимация каждого control. Existing Reader page turn 180 ms и controls fade 200 ms сохраняются. Пространственный переход ДОЛЖЕН быть прерываемым; correctness не зависит от animation-end.

### MOT-02 Запреты

Нет scale/glow для фокуса, ripple waves для обычного press, полноэкранного fade между повседневными действиями, auto-rotating carousel и декоративного parallax. Reduced motion убирает сдвиг/непрерывную анимацию, оставляя текст состояния. Hidden controls исключены из input/accessibility tree.

## 13. Доступность и сохранность

### A11Y-01 Минимум

Controls ДОЛЖНЫ иметь targets ≥48 dp, native role/name/state, доступный keyboard/D-pad путь и читаемый focus. Текст — sp. 2× font scale, Light/Dark и short landscape проверяются отдельно. См. [Android accessibility](https://developer.android.com/design/ui/mobile/guides/foundations/accessibility).

Смысл не передаётся только цветом или жестом. Имена контекстные. Decorative icon не дублирует текст. Ошибка остаётся рядом с полем. IME, парольный manager, paste и системный Back не заменяются самодельными средствами без предметной причины.

### STATE-01 Сохранение

При Back, dialog, theme/font/window change ДОЛЖНЫ сохраняться content ID, query, scroll, позиция/anchor и логический selection. Resize без Activity recreation обязателен для широких окон/Fold. Скрытие reader controls не сдвигает текст.

Не запускать disk/network/import/полную разметку больших книг на UI thread. Ограничивать декодирование изображений и объём отображаемых элементов. Поздний async result не должен перезаписывать новый screen state.

### DATA-01 Совместимость

Сохраняются applicationId, signing identity, native channels, network identity и существующие миграции. Ребрендинг не меняет API headers или серверный контракт. Нельзя предлагать uninstall как способ обновления с сохранением данных.

Не обещать cloud sync/backup: у Reader сейчас их нет. Неотслеживаемые Watch server-management материалы являются проектами, не подтверждёнными возможностями.

В HTML-руководстве эти правила сопровождаются образцами состояний, swatches, таблицей контраста и реальными изображениями приложений. Плохие варианты там явно помечены и не являются альтернативной темой.

## 15. Применение к трём стекам

### IMP-01 Карта реализации

| Контракт | Reader / Views | Anime / Flutter | Watch / Compose |
| --- | --- | --- | --- |
| Color roles | ReaderOptions | mjTheme в ui.dart | Theme.kt, MaterialTheme.colorScheme |
| Состояния | Existing native drawing/selectors + View semantics | TvButton, FocusNode, Semantics | NativeCard/Action, focus/semantics |
| Иконки | ReaderIcon | Existing Material icons | Icons.Outlined |
| Layout | observeWindow, existing adapters | Existing Shell/cinema widgets | Mobile/TV оболочки, adaptive layout |
| Reader/video state | Full-text anchors | Session + player state | WatchModel/core/playback |
| Проверки | checks.sh + custom Android runner | make check/native-test + exact APK | check.sh + mobile/TV instrumentation |

`tokens.json` — данные спецификации, а не новая runtime dependency. Внедрение переносит роли в existing theme/helpers. Генератор Kotlin/Dart/Java не нужен до появления реальной потребности. Само наличие design-system module не означает, что весь его app/state код следует переносить в другие продукты.

### IMP-02 Шаблон задачи унификации

```text
Экран/компонент:
Проблема пользователя:
Правила стандарта:
Текущее и целевое поведение:
Состояния: normal/focus/selected/loading/error/empty/large-font
Платформы и ввод:
Совместимость данных/подписи/сети:
Снимки до/после при одинаковом окне:
Проверки и ограничения:
```

Нельзя закрыть задачу словом «приведено к дизайну» без указания состояний и проверок. Необязательные для компонента состояния помечаются неприменимыми с краткой причиной.

## 16. Миграция и выпуск

### MIG-01 Порядок

1. Связать README/AGENTS с одним стандартом; убрать конфликтующие указания, сохранив history.
2. Watch: разделить launcher/banner, проверить новый предметный символ; Anime: сверить точную геометрию с Reader master.
3. Отобразить tokens на текущие themes; Watch явно согласовать error-роли.
4. Привести shared controls к focus/selected/large-font требованиям.
5. Проверить реальные экраны: Watch hero и подготовка, Anime episodes/history, Reader adaptive/dialog/preview.
6. Обновить demo screenshots и checks/release документацию; закрыть миграционные задачи по критериям.

Приоритет: сохранность/управляемость → доступность/идентичность → визуальная настройка. Один небольшой PR на компонент или связанный сценарий. Не менять версии, зависимости, серверы и подписи вместе с косметикой без прямой необходимости.

### REL-01 Проверяемый выпуск

Commit → обязательные checks → версия/тег → подписанный APK → проверка package/version/cert/hash → release. Стабильный выпуск явно по тегу; автоматический testing МОЖЕТ существовать отдельным каналом, как в Watch. Debug runtime не доказывает signed release.

Auto check не означает auto download. Суточный интервал Anime и 15 минут Watch — продуктовая политика, не визуальное расхождение. Сохранность библиотек, истории и настроек при update проверяется предметно.

## 17. Приёмка и управление стандартом

### QA-01 Матрица

| Область | Обязательная проверка |
| --- | --- |
| Theme | Dark/Light; Reader дополнительно Dusk/Sepia в затронутом control |
| Размер | Узкое окно, обычное, широкое; высота <400 dp при применимости |

| Сохранение | Back, dialog, resize, theme/font, recreation при применимости |
| Артефакт | Точный финальный APK для release/video/GPU поведения |

### QA-02 Чеклист готовности

- [ ] Правила и исключения указаны в задаче.
- [ ] Одно основное действие в контексте; остальные доступны и понятны.
- [ ] Цветовые роли и разрешённые пары соблюдены.
- [ ] Все targets ≥48 dp; focus отличим от selected и не обрезан.
- [ ] Нет потери query/position/selection при переходах и resize.
- [ ] Large font и короткое окно не прячут действия.
- [ ] Ошибка объясняет причину/восстановление и сохраняет ввод.
- [ ] Изображения принадлежат объекту и не выдумывают данные.
- [ ] Снимки до/после сопоставимы; проверки соответствуют уровню заявления.
- [ ] Документация, ресурсы, лицензии и release identity согласованы.

### GOV-01 Источник истины

Этот файл — нормативный текст; `tokens.json` — его числовое отображение; `guide.html` — переносимое иллюстрированное представление. `RESEARCH.md` — аналитическое основание, не второй нормативный документ. При изменении значения обновляются оба source-файла и пересобирается HTML.

Для 1.x совместимые уточнения сохраняют ID. Смена семантики действия, branded geometry или обязательного контракта оформляется явным решением с миграцией. Исключения записываются в `docs/DESIGN.md` конкретного приложения.

Пример исключения: «MJReader / TYP-01: гарнитура текста книги выбирается пользователем; UI остаётся на общей scale. Проверка: смена гарнитуры сохраняет full-text anchor». Пример нерешённого выбора: точный app symbol Watch; его нельзя незаметно закрепить только в HTML-примере.

### GOV-02 Что считается доказательством

Статический разбор подтверждает наличие кода, widget/native render — конкретный внешний вид, установленный APK — соответствующее runtime-поведение, реальное устройство/сервис — только проверенный сценарий. Screenshot не доказывает TalkBack, GPU pipeline, server compatibility или скорость.

Для Reader runner требует ожидаемый PASS, не только exit code ADB. Условия доступа к устройствам и аккаунтам остаются локальными правилами проекта. Документальная правка не требует запуска приложений и публикации APK.
