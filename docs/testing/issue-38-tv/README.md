# Issue #38 — MKV на Android TV: повторное расследование

Пользователь сообщил: Xiaomi L1 Pro, при запуске MKV показывается «Формат не поддерживается». Issue #38 переоткрыт. Пользователь подтвердил актуальную версию и воспроизведение той же раздачи на телефоне; имя раздачи и файла сейчас недоступно. Причина на проекторе не установлена; исправление конкретного файла на Xiaomi не подтверждено.

Предыдущая MatroskaPlaybackTest находилась только в app-mobile: TV-контролы на телефоне не проверяли TV APK/Android TV. В app-tv добавлен тот же настоящий H.264/AAC MKV из debug-ресурса с extensionless URI и исходным именем Show.S01E01.MKV.

Локально 1/1 passed: TV APK на Android TV API36 arm64-v8a, 1920×1080, native features android.hardware.type.television / android.software.leanback_only / com.google.android.tv.installed. Проверены первый кадр, отсутствие playerError, аудио- и видеотреки, длительность и seek. [Сырой результат](native-tv-runtime.txt). Этот результат доказывает работу конкретного H.264/AAC контейнера в TV APK на эмуляторе, но не работу файла пользователя на Xiaomi.

Текущий обработчик объединяет коды Media3 4000…5999 под одной надписью. Для определения причины нужен проблемный файл или точные сведения о дорожках/ошибке. В 0.9.6 включён штатный `DefaultRenderersFactory.setEnableDecoderFallback(true)`: при сбое инициализации основного декодера Media3 пробует следующий доступный. Это не добавляет отсутствующие у Android кодеки и не является подтверждением исправления Xiaomi. [Поведение Media3](https://developer.android.com/reference/androidx/media3/exoplayer/DefaultRenderersFactory#setEnableDecoderFallback(boolean)).

Сообщения теперь различают ошибки контейнера (3001/3003), инициализации (4001/4002), неподдерживаемую дорожку/параметры (4004/4005), декодирования и вывода звука. Показываются только код, MIME и сведения о дорожке (codec string, размеры или число каналов), без URL, заголовков, токенов или текста исключений. Сетевое восстановление сохранено.

Локальная окончательная проверка: 13 playback unit-тестов без ошибок/пропусков, обе debug-сборки, обе lintDebug. [Лог](decoder-build.txt). Исходный MKV-тест Android TV выше выполнен до включения fallback; финальный TV APK с изменениями должен пройти штатный CI перед публикацией. Issue #38 не закрывается без проверки на Xiaomi.

В первом релизном прогоне 119 новый MatroskaPlaybackTest прошёл на Android TV. BufferingUiTest выявил регрессию классификатора: ошибка контейнера 3003 скрывала ручной «Повторить». Повтор восстановлен для ошибок чтения контейнера и сети, как раньше; unit-регрессия фиксирует это условие. Изменение проверяется до публикации, без ослабления runtime-теста.

В прогоне 120 MatroskaPlaybackTest и BufferingUiTest прошли. Один неизменённый TvPlayerBehaviorTest получил timeout в финальном выходе по Back (строка 178), ранее проявлявшийся в PR #46. TV job перезапущен отдельно; проверки не отключались и утверждения не ослаблялись.

Повтор TV job 120 прошёл первый сценарий выхода, но получил timeout другого сценария возврата фокуса после диалога (прежняя строка 219). Вместо дальнейших повторов TvPlayerBehaviorTest теперь ждёт подтверждённого фокуса перед нажатием, фактического фокуса окна Compose-диалога на API29+ и промежуточных состояний «timeline → скрытые контролы» перед Back. Сами проверки возврата фокуса/выхода оставлены; добавлены более точные промежуточные утверждения. Производственные TV-контролы не изменены. Компиляция instrumentation и lint прошли — [лог](focus-test-build.txt).
