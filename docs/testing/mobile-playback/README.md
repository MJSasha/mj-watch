# Просмотр на телефоне после связки с TV

База: `8742f513f1848992e97c425d5f06eeb3d954ac49`, main / 0.9.1. Работа выполнена в отдельном worktree, ветка `codex/mobile-playback-fix`; исходная ветка 0.8.16 и её материалы не менялись.

## Причина и исправление

В 0.9.1 мобильные `playRelease`/`resume` и кнопки выбора раздачи/файла зависели от `remote.canLaunch`. Мобильная ветка запуска всегда отправляла файл на TV. Поэтому без готового приёмника выбранная раздача подсвечивалась, но запустить её на телефоне было нельзя.

Возвращён явный локальный маршрут и отдельный запуск на TV. Локальные «Смотреть на телефоне» и «Продолжить» работают независимо от состояния TV; удалённый запуск сохраняет проверку связи, профиля и смены адресата. При локальном запуске выключается Android-сессия дистанционного пульта, чтобы системные кнопки управляли местным плеером. Это не посылает TV команду остановки. Шапка мобильного списка прокручивается, кнопки запуска остаются под списком. Сохранение прогресса, база и серверный протокол не менялись.

## Воспроизведение

До исправления APK, собранный из указанной main, не проходит `PlaybackAfterPairingTest`: настоящие HTTPS pairing/approve создают отдельную TV-сессию и сохраняют телефонную сессию, но после выбора раздачи отсутствует `source-continue`. [Лог](before.txt), [выбранная строка без кнопки](before.png).

После исправления в том же сценарии кнопка видна и локальный Media3 получает первый кадр через HTTPS-шлюз: [кнопка запуска](after.png), [воспроизведение](phone-first-frame.png).

## Проверки

- 65 core + 12 playback unit-тестов: без ошибок и пропусков.
- Mobile/TV lintDebug, обе debug-сборки и сборка мобильных androidTest: успешно.
- Основной runtime: 10 passed + 1 skipped (проверка пустого поиска только для короткого окна) в [runtime.txt](runtime.txt). Новый просмотр после настоящего pairing, продолжение сериала с 4000 мс с локальной ссылкой и без неё, ошибка недоступной legacy-раздачи, локальная навигация, поиск и поворот экрана.
- Фильтр сезонов → локальный запуск: 1 passed, [лог](filters.txt).
- Компактное окно 420×500 dp, fontScale=2.0: оба маршрута выбора прошли повторно, 2 passed, [лог](compact.txt).
- SHA-256 проверенного mobile debug APK: `e674cd0de6564bac261639a272d153c6c31aba608e50bf2db0e8f26fb3f89b75`. [Сборка и lint](build.txt).

Использован только собственный эмулятор Android API36, отдельный тестовый Go/SQLite/HTTPS-сервер и локальное тестовое видео. Pairing проверен через настоящий зашифрованный inbox и серверный approve; оптическое сканирование и физический телевизор в этот прогон не входят. Доступность приёмника в `PhonePlaybackRouteTest` моделируется: проверяется независимость локального просмотра и отдельный маршрут TV, без заявления о новом end-to-end прогоне четырёх устройств. `PhoneTvTest` обновлён для явной TV-кнопки, но в этот прогон не запускался.

Тестировались локально собранные debug APK. Опубликованный APK скачан для сверки версии; установить его поверх debug нельзя из-за другой подписи. На момент локальной проверки выпуск ещё не публиковался; результат выпуска приведён ниже.
